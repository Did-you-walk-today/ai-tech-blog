# post-images — 포스트 이미지 워크플로

## 역할 분담 (먼저 이해할 것)

| 주체 | 하는 일 |
|---|---|
| Claude Code | 이미지 **계획**, **프롬프트 작성**, **alt 작성**, **규격 정규화**, **검증** |
| Codex (또는 이미지 모델) | 실제 이미지 **생성** |
| 기웅 | 프롬프트를 Codex에 투입, 결과 파일을 `assets/img/posts/`에 배치 |

Claude Code는 이미지를 만들 수 없다. 만들 수 있는 척하지 말고, 프롬프트 팩을
정확하게 만들어 넘기는 데 집중한다.

## Step 0 — 필독

- `IMAGE_GUIDE.md` **전체** (원칙 5개 / 개수 / 규격 / 스타일 토큰 / 금지사항)
- 대상 포스트의 frontmatter (`format`, `slug`, `title`, `description`)와 본문

## Step 1 — 이미지 계획

포스트의 `format`으로 개수를 정한다 (`IMAGE_GUIDE.md` §2). 상한 5장.

계획 결과를 표로 먼저 제시한다 — 파일명, 용도, 그 이미지가 **주장할 사실 1개**.
주장할 사실을 한 문장으로 못 쓰면 그 이미지는 장식이다. 계획에서 뺀다.

**수치가 들어가는 차트는 이 스킬에서 다루지 않는다.** `_data/` JSON을 입력으로
`dataviz` 스킬을 읽고 SVG를 직접 생성한다. 이미지 모델에 숫자를 맡기는 것은
`IMAGE_GUIDE.md` P1 위반 = 하드 리젝.

## Step 2 — 프롬프트 팩 작성

`_reviews/YYYY-MM-DD-{slug}.images.md`에 작성한다. 필수 구성:

1. **대상**: 슬러그 / 포맷 / 총 장수
2. **이미지별 블록** — 각각에:
   - 파일명 (`{slug}-cover.png` 등)과 저장 경로
   - 규격 (커버 1200×630 PNG ≤200KB / 본문 WebP 가로 ≤1600px ≤150KB)
   - **완성 프롬프트** — `IMAGE_GUIDE.md` §5 STYLE 블록을 글자 그대로 포함해
     복사·붙여넣기만 하면 되는 상태. 요약하거나 줄이지 않는다
   - alt 텍스트 초안 (영어, 125자 이내, 주장 문장)
   - **근거 대응표** (`IMAGE_GUIDE.md` §8 형식) — 아래 참조
3. **반입 후 명령** — §9 최적화 + §10 검증 명령을 그대로

### 근거 대응표는 선택이 아니다

그림에서 값을 나타내는 요소(길이·개수·위치·순서·끝점)를 **빠짐없이** 나열하고
각각을 본문 수치에 대응시킨다. 대응이 없는 요소는 그림에서 지운다.

훅 C10이 이 표의 존재를 검사한다. 표 없이 본문 도식을 넣으면 WARN이 뜬다.

작성 순서를 지켜라 — **표를 먼저 쓰고 프롬프트를 나중에 쓴다.** 프롬프트를 먼저
쓰면 "그럴듯한 그림"을 정당화하는 표가 나온다. 순서를 뒤집으면 본문에 근거가 없는
요소는 애초에 프롬프트에 들어가지 않는다.

### T1~T7 자가 점검 (프롬프트 확정 전)

`IMAGE_GUIDE.md` §6-4를 읽고 7개 규칙을 하나씩 대조한다. 특히 자주 터지는 것:

- **T1** 형태로 표현한 비율 = 본문 실제 비율인가
- **T2** 본문이 "미공개"라고 한 값에 형태를 부여하지 않았는가
- **T7** 본문이 여러 갈래로 갈린다고 말하는데 그림은 하나로 압축하지 않았는가

이 3개는 2026-07-25 `best-llm-2026`에서 실제로 전부 위반됐고, 규격 검사는
100% 통과했다. **훅이 잡아주지 못하는 영역이므로 여기서 막아야 한다.**

프롬프트 팩은 한국어 설명 + 영어 프롬프트로 쓴다 (프롬프트는 모델 입력이므로 영어).

### 커버 프롬프트 작성법

커버는 제목의 삽화가 아니라 **핵심 주장 1개의 시각적 은유**다.
"주제가 LLM 비교니까 로고 나열" 같은 접근은 거부한다.

1. 포스트의 TL;DR에서 가장 강한 주장 1개를 고른다
2. 그 주장을 형태 관계로 번역한다 (수렴/발산, 계층, 분기, 비대칭)
3. 텍스트·숫자 없이 그 형태만 서술한다

## Step 3 — 기웅에게 핸드오프

프롬프트 팩 경로와 계획 표를 한국어로 보고한다. 다음 문장을 반드시 포함:

> Codex에 프롬프트를 넣고 나온 파일을 `assets/img/posts/`에 두신 뒤 알려주세요.
> 규격 정규화와 검증은 제가 이어서 합니다.

여기서 멈춘다. 이미지가 없는 상태로 발행 단계를 진행하지 않는다.

## Step 4 — 반입 파일 정규화

기웅이 파일을 배치했다고 알리면:

```bash
python3 .claude/hooks/optimize_image.py assets/img/posts/{slug}-cover.png --cover
python3 .claude/hooks/optimize_image.py assets/img/posts/{slug}-fig1.png --figure
```

정규화 후 원본 PNG(본문 이미지의 경우)는 삭제한다 — 레포에 중복 자산을 남기지 않는다.

## Step 5 — 반입 검증 (육안 확인 포함)

규격은 스크립트가 잡는다. 나머지는 **Read 툴로 이미지를 직접 열어** 확인한다.
스크립트는 그림이 무엇을 말하는지 모른다 — 이 단계를 건너뛰면 검증이 없는 것과 같다.

**금지 요소 (`IMAGE_GUIDE.md` §7)**

- 이미지 안에 텍스트/숫자/로고가 구워져 있는가 (가장 흔한 실패)
- 사람 얼굴·손·뇌·로봇·빛나는 구체 등 금지 요소가 있는가
- 해칭·빗금 등 채움 패턴을 썼는가
- 실제 제품 UI를 모사했는가

**의미 검증 (§6-4 T1~T7)** — 근거 대응표를 옆에 놓고 그림과 한 행씩 대조한다:

- 표에 적은 비례가 그림에서 실제로 그렇게 그려졌는가 (렌더러가 무시했을 수 있다)
- 표에 없는 요소가 그림에 생겼는가 (모델이 추가했을 수 있다)
- 다단계 도식이면 개체가 단계마다 같은 도형을 유지하는가 (T3)
- "좁혀진다"는 도식이면 개수가 단조 감소하는가 (T4)

측정이 필요하면 픽셀을 직접 재라. 눈대중으로 "비슷해 보인다"는 검증이 아니다:

```python
from PIL import Image
im = Image.open('assets/img/posts/{slug}-cover.png').convert('RGB')
# 특정 y행에서 배경색이 아닌 x 좌표의 min/max로 선분 길이를 잰다
```

하나라도 걸리면 프롬프트를 보강해 재생성을 요청한다. "대충 쓸 만하니 통과"는 없다.

## Step 6 — 포스트 반영 및 최종 검증

- frontmatter `image.path` / `image.alt` 갱신
- 본문 이미지는 마크다운 + 캡션 한 줄로 삽입 (`IMAGE_GUIDE.md` §4)
- 검증:

```bash
python3 .claude/hooks/image_validation.py --report
```

대상 슬러그가 `OK`가 되어야 한다. `_posts/`에 ERROR가 남아 있으면 발행 불가.

## 백필 모드 (기존 포스트 일괄 처리)

`--report`로 커버 누락 포스트를 뽑아 오래된 순으로 처리한다.
한 번에 3개까지만 프롬프트 팩을 만든다 — Codex 투입과 검증이 사람 작업이라
쌓아두면 검증이 형식화된다.

발행된 포스트의 커버를 추가/교체한 뒤에는 `last_modified_at`을 갱신하고,
소셜 카드 캐시(트위터/링크드인/슬랙)는 각 플랫폼 캐시 만료 전까지
옛 404 상태를 들고 있을 수 있음을 보고에 명시한다.
