- 대상 포스트의 frontmatter (`format`, `slug`, `cluster`, `title`)와 본문

## 갈림길 — 이 이미지는 본문의 값을 주장하는가

모든 판단이 여기서 갈린다. 계층을 섞으면 반드시 사고가 난다.

| | 클래스 A — 커버 | 클래스 B — 서술 도형 |
|---|---|---|
| 값 주장 | 없음 | 있음 |
| 생성 주체 | **기웅** — 이미지 생성 모델로. Claude Code는 생성하지 못한다 | **Claude Code가 직접 코드로** |
| 사람 개입 | 프롬프트 승인 + **생성 실행** + 육안 검수 | 육안 검수만 |
| 경로 | Step 1A → 2A → 3A | Step 1B → 2B → 3B |

**클래스 B에 이미지 모델을 쓰는 것은 하드 리젝이다** (`IMAGE_GUIDE.md` P1).
2026-07-25에 이 경계를 넘어서 3장 전부 폐기했다.

## 경로 A — 커버 (모든 포스트 1장, 필수)

### Step 1A — 소재 선택

커버는 **포스트 내용과 무관해도 된다.** 오히려 무관한 편이 안전하다 —
아무것도 주장하지 않으면 틀릴 수 없기 때문이다.

1. 포스트의 `cluster`를 확인한다
2. `IMAGE_GUIDE.md` §8 소재 풀에서 그 클러스터의 시각 세계를 고른다
3. 그 안에서 **구체적인 실물 오브젝트 1개**를 정한다
4. 같은 클러스터의 최근 커버 3장과 소재가 겹치지 않는지 확인한다

포스트의 주장을 시각적 은유로 번역하려 하지 마라. 그게 이전 판의 실패 원인이다.

### Step 2A — 프롬프트 작성 (전달본은 한국어 리뷰 리포트)

**완성 프롬프트 전문은 `_reviews/YYYY-MM-DD-{slug}.ko.md`의 "커버 이미지 프롬프트"
섹션에 쓴다.** 기웅이 검토하려고 어차피 여는 파일이고, 터미널 답변에서 복사하면
줄바꿈이 유실되거나 선택 영역이 잘려 §6 스타일 토큰이 빠진 채 모델에 들어간다
(`IMAGE_GUIDE.md` §10, 2026-08-21 규칙 변경).

리뷰 리포트의 이미지 섹션:

1. `IMAGE_GUIDE.md` §7 템플릿에 §6 스타일 블록을 **글자 그대로** 넣은 완성 프롬프트
   — 요약하거나 줄이지 않는다
2. 가로세로비 `16:9`, 저장 경로, "이미지 생성 모델로 만들 것 / 코드로 그리지 말 것"
3. alt 초안 — **장면 서술**이다. 데이터 주장을 쓰면 하드 리젝 (`IMAGE_GUIDE.md` §5)

이미지 팩 `_reviews/YYYY-MM-DD-{slug}.images.md`에는 **프롬프트 전문을 다시 쓰지 않고**
리뷰 리포트의 해당 섹션을 가리킨다. 팩이 담는 것은:

1. 대상 슬러그 / 포맷 / 클러스터 / 선택한 소재와 그 근거(클러스터 매칭 + 최근 3장 중복 회피)
2. P6 위험 점검 — 값으로 읽힐 요소가 있는지
3. 저장 경로와 규격, 반입 검증 로그
4. 서술 도형 판단 (만들지 않기로 했다면 그 근거)

전문을 두 파일에 복사해 두지 않는다 — 한쪽만 고쳐지면 어느 쪽이 실제 생성에 쓰였는지
알 수 없게 된다.

커버에는 **근거 대응표가 없다.** 대응시킬 값이 없기 때문이다.
표를 쓰고 싶어진다면 그 커버는 값을 그리고 있다는 뜻이고, P6 위반이다.

### Step 3A — 기웅에게 생성을 요청한다

**Claude Code는 이미지를 생성하지 못한다.** 코드로 그린 SVG/PNG는 `IMAGE_GUIDE.md` §11
하드 리젝이고 훅 C11이 색상 수로 잡아낸다. 그러므로 이 단계는 실행이 아니라 **요청**이다.

요청 답변은 **프롬프트가 들어있는 파일과 섹션을 가리킨다.** 프롬프트 전문을 답변에
붙여넣지 않는다 — 터미널에서 복사가 실패해 스타일 토큰이 잘린 채 모델에 들어간다
(2026-08-21 규칙 변경, `IMAGE_GUIDE.md` §10):

1. **전달 위치** — `_reviews/YYYY-MM-DD-{slug}.ko.md`의 "커버 이미지 프롬프트" 섹션
2. 가로세로비 **16:9** — 1200×630은 대부분의 모델이 직접 생성하지 못한다
3. 저장 경로 `assets/img/posts/{slug}-cover-raw.png`
4. **"이미지 생성 모델로 만들 것, 코드로 그리지 말 것"**

2~4는 리뷰 리포트 안에도 적혀 있어야 한다. 답변은 그 요약일 뿐이다.

도구는 고정하지 않는다. 기웅이 쓸 수 있는 이미지 생성 서비스면 되고, 아래 검증만
통과하면 출처는 묻지 않는다. **웹앱 경로가 CLI보다 안전하다** — 코딩 에이전트 CLI는
이미지 모델을 명시적으로 요구하지 않으면 Python/SVG로 그린다.

### Step 3A-2 — 반입 검증 (순서 고정)

**1) 파일이 실제로 왔는지 확인한다.** Codespaces는 원격이라 로컬 다운로드는 오지 않는다.
파일명은 벤더가 붙인 그대로일 수 있으니 이름이 아니라 **생성 시각**으로 찾는다:

```bash
find . -type f \( -iname "*.png" -o -iname "*.jpg" \) -newermt "YYYY-MM-DD" \
  -not -path "./_site/*" -not -path "./node_modules/*"
```

**2) 색상 수** — 이미지 모델 산출물인지 가리는 유일한 증거. 벤더 무관:

```bash
python3 -c "
from PIL import Image; im=Image.open('경로').convert('RGB')
n=len(im.getcolors(maxcolors=99999999) or [])
print(im.size, n, 'colors', '→ OK' if n>5000 else '→ 코드 렌더. 폐기하고 재요청')"
```

정규화하면 색상 수가 절반 가까이 줄어든다. 최종 `.jpg`를 검사하는 훅 C11의
기준선은 1,000이다 (`IMAGE_GUIDE.md` §10).

**3) 워터마크** — 생성 표식이 구워져 오는 벤더가 있다. **지우지 말고 크롭으로 프레임
밖에 둔다.** 리터칭은 §11의 출처 표시 제거 금지 위반이다. 좌우 폭부터 줄인다 —
상하를 깎으면 §7이 확보한 안전 여백을 이중으로 잃는다.

**4) 크롭·정규화** — 40:21 정수비로 잘라 리사이즈 왜곡을 없앤 뒤 정규화한다:

```bash
python3 .claude/hooks/optimize_image.py assets/img/posts/{slug}-cover-raw.png --cover \
    -o assets/img/posts/{slug}-cover.jpg
rm assets/img/posts/{slug}-cover-raw.png
```

> **레터박스 오진 주의.** 행·열의 **최대값**으로 검은 밴드를 찾으면 피사체가 시작하는
> 지점을 경계로 오독한다. **평균**으로 판정한다 — 균일하면 밴드가 아니라 어두운 배경이다.

검증 결과와 워터마크 처리 판단은 팩 파일에 기록한다.

## 경로 B — 서술 도형 (기본값 0장)

### Step 1B — 정말 필요한지 먼저 묻는다

표로 표현 가능하면 표를 쓴다. 도형은 **흐름·계층·시간축처럼 표가 표현하지 못하는
관계**에만 쓴다. 포맷별 예산은 `IMAGE_GUIDE.md` §3.

### Step 2B — 근거 대응표를 **먼저** 쓴다

`_reviews/YYYY-MM-DD-{slug}.images.md`에 작성한다. 순서를 지켜라 —
**표를 먼저 쓰고 코드를 나중에 쓴다.** 코드를 먼저 쓰면 "그럴듯한 그림"을
정당화하는 표가 나온다.

| 그림 요소 | 나타내는 것 | 본문 근거 | 실제 값 | 그림에 반영한 값 |
|---|---|---|---|---|

- **"본문 근거"가 비는 행이 있으면 그 요소를 그림에서 지운다.** 예외 없다
- "실제 값"과 "그림에 반영한 값"이 다르면 그 차이가 정당한 이유를 한 줄로 적는다
- 독자가 값으로 오독할 수 있는 요소는 장식이 아니다 — 표에 넣는다

훅 C10이 이 표의 존재를 검사한다.

### Step 3B — 코드로 생성

Claude Code가 직접 만든다. 사람에게 넘기지 않는다.

- **수치 차트** → `dataviz` 스킬을 읽고 SVG 생성
- **도식(흐름·계층·관계)** → Python으로 SVG 문자열 생성
- 스타일 토큰은 `IMAGE_GUIDE.md` §9

값은 **`_data/YYYY-MM-DD-{slug}.json`에서 읽거나 상수 배열로 선언**하고,
좌표는 그 값에서 계산한다. 좌표를 손으로 적는 순간 T1이 깨진다.

T1~T7을 코드에 `assert`로 박는다:

```python
assert stages == sorted(stages, reverse=True), "T4: 단계별 개수가 단조 감소가 아님"
assert sum(dropped) + stages[-1] == stages[0], "T5: 회계 불일치"
assert len(thresholds) == 4, "T7: 본문은 4종인데 그림이 다름"
```

미공개 값은 `None`으로 두고 **끝점 없는 열린 선**으로 렌더한다 (T2).
임의의 길이를 대입하면 본문에 없는 사실을 그림이 만들어낸다.

## Step 4 — 육안 검수 (건너뛰기 금지)

규격은 스크립트가 잡는다. 의미는 못 잡는다. **`Read` 툴로 이미지를 직접 연다.**

**커버 (클래스 A)**

- 값으로 읽히는 요소가 있는가 — 막대, 축, 눈금, 읽히는 계기판, 셀 수 있는 반복 요소 (P6)
- `IMAGE_GUIDE.md` §6 AVOID의 금지 소재 — 로봇·사람·뇌·회로기판·홀로그램 HUD·구워진 텍스트
- alt가 장면 서술인가, 데이터 주장인가
- 상하 크롭 후에도 주요 피사체가 온전한가

**서술 도형 (클래스 B)**

근거 대응표를 옆에 놓고 한 행씩 대조한다. 측정이 필요하면 픽셀을 직접 잰다 —
눈대중으로 "비슷해 보인다"는 검증이 아니다:

```python
from PIL import Image
im = Image.open('assets/img/posts/{slug}-fig1.png').convert('RGB')
# 특정 y행에서 배경색이 아닌 x 좌표의 min/max로 선분 길이를 잰다
```

하나라도 걸리면 재생성한다. "대충 쓸 만하니 통과"는 없다.

## Step 5 — 포스트 반영 및 최종 검증

- frontmatter `image.path` (`.jpg`) / `image.alt` 갱신
- 서술 도형은 마크다운 + 캡션 한 줄 (`IMAGE_GUIDE.md` §5)
- `python3 .claude/hooks/image_validation.py --report` → 대상 슬러그가 `OK`

## 백필 모드 (기존 포스트 일괄 처리)

`--report`로 커버 누락·구버전 포스트를 뽑아 오래된 순으로 처리한다.
**한 번에 3개까지만** — 생성과 검수가 모두 기웅의 작업이라 쌓아두면 형식화된다.
백필도 요청 단위다: 프롬프트 3건을 한 답변에 나열하지 말고, 한 건씩 생성·반입·검증을
끝낸 뒤 다음으로 넘어간다. 여러 건을 동시에 던지면 어느 파일이 어느 프롬프트의
산출물인지 추적이 끊긴다.

3~4색 코드 렌더 커버 12장의 `.jpg` 재생성 백필은 2026-07-28에 완료됐다.
남은 `-cover.png`는 없고, 검증기도 더 이상 `.png` 커버를 봐주지 않는다.

발행된 포스트의 커버를 교체한 뒤에는 `last_modified_at`을 갱신하고,
소셜 카드 캐시(트위터/링크드인/슬랙)가 옛 이미지를 들고 있을 수 있음을 보고에 명시한다.
